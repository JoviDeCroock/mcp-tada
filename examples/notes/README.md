# notes example

End-to-end use of both packages.

- `src/tools.ts` declares four tools with `defineTool`, three with an `outputSchema`, and annotates which are read-only or destructive.
- `src/server.ts` registers them on an `McpServer` over stdio with output validation on.
- `src/notes.introspection.d.ts` is generated by `pnpm introspect` from the running server and committed.
- `src/client.ts` spawns the server, wraps the SDK client with `initMcpTada<introspection>()`, and shows typed calls, `isError` narrowing, a `readOnly` view limited to the read-only tools, and that the CLI snapshot and `IntrospectionOf<typeof tools>` describe the same server.
- `src/client-v1.ts` is the same client on the v1 SDK (`@modelcontextprotocol/sdk`): it uses the legacy handshake, since `initMcpTada` accepts either SDK's client.

```sh
pnpm introspect   # rebuild the server and regenerate the snapshot
pnpm check        # fail if the running server drifted from the snapshot
pnpm start        # run the typed client against the server
pnpm start:v1     # the same, through the v1 SDK's Client
```

The server uses `serveStdio` to serve both protocol eras. The v2 client and snapshot config opt into modern negotiation with `auto`; the v1 client uses the legacy handshake against the same server.
